# generated silences screen against the fixed screen, checkpoint b of task-69

Checkpoint b of task-69 asked whether a screen generated from an intent is better to use than a well-drawn fixed screen for the same task: reviewing the silence cuts of a video in the Silences app. The orchestrator ran both through the agent contract and photographed them in a 1200x800 window, in two rounds with fixes between them. The first round found the generated screen worse to use; the second found it had stopped being worse, a tie with different advantages, so generation stayed the main line of the program.

## Question

The task's phase 0 asked whether a surface that appears for one task is better than the fixed screen. That spike did not run; the orchestrator's decisions moved the question to checkpoint b, where the generated surface is compared with a well-drawn fixed screen for the same task and the result is written down. The acceptance criterion says the comparison is made with brenner. The program fixed the consequence in advance: if the generated screen is worse, task-70 goes to transformation over fixed screens. The task's risk section names the open possibility: the hypothesis that a generated surface is better may fail.

## Setup

- **Task.** Review the silence cuts of one video: see the detected cuts and apply or reject each one. The task's own example is "cut the silences of this video, then I want to review the cuts".
- **Fixed screen.** The Silences page of the showcase, with the real detection of the video's silences.
- **Generated screens.** The same intent given to a proposer, chosen with the `proposer` action: `rules` (deterministic, instant, free) or `claude` (Claude; each round records its time, attempts and cost).
- **Method.** The showcase runs with `PLEV_AGENT=1 PLEV_MIRROR=1 PLEV_BACKGROUND=1 PLEV_RECORD=1`. Each step is taken with `plev act` as agent `orquestrador`, and each screen is photographed by the mirror (task-79, `mirror --frames 1 --png`). Window 1200x800.
- **Intents.** The round-1 page does not record the intents. The re-run script in the corrections page gives "the list with the video and the counts" for the rules screen and "cut the silences of this video, then I want to review the cuts" for the Claude screen. The round-2 page notes that the Claude intent begins with "cut the silences".
- **Binary and commit.** Round 1: not recorded. Round 2: the main binary after the fixes (PR #92). The fixes were made on branch `task/69i-checkpoint-b`, on main `5cfb0dfb`.
- **Machine.** Not recorded, except in round 2: a retina display, 2400x1600 physical pixels, 1200x800 logical. The round-2 images were reduced to 1200 px wide.
- **Claude model.** Not recorded.
- **After-fix Claude view.** It is not a new Claude run. It is a review built from the round-1 observation, verified by the `uir` verifier against the app's registry and shown through the regress harness.

**Verdict, round 1.** The generated screen is worse to use today. The round names two implementation causes that apply to every generated screen (the row shrinks in a narrow column; numbers have no format) and one cause in the proposal (the task comes last, and the screen repeats what the fixed one shows). No reference image covered the open generated screen, so the layout defect passed every phase. The orchestrator decided to fix before applying the rule: the defects are core bugs, and the checkpoint runs again with the same images. The program's rule did not change.

**Probe.** The corrections page reproduces the defects at 1200x800 with a fake worker. The surface column runs from x = 740 to 1160 (420 px). The rules card has `padding: lg` (20 px), so the cut row is 380 px. Its five texts are 9 to 10 px wide and 158 to 360 px tall, one character per line, while the longest word of each measures 43.8 to 63.8 px. The buttons "preview segment", "apply cut" and "reject cut" end at x = 1107, 1224 and 1341; the last is 181 px past the card edge. The Claude fixture repeats the defect: its track is 9 px wide and its buttons reach x = 1348.

**Verdict, round 2.** The generated screen stopped being worse. For the task of reviewing cuts, the Claude screen is more direct than the fixed one in the default window: both cuts and their actions are in view without scrolling, and the person decides from there. The fixed screen informs more per cut, with the frame and the duration, and the frame is how a person sees what will be cut. The source calls this a tie with different advantages, not a defeat for generation. Because the central hypothesis did not fail, the source records no stop reason. Under the program's rule, generation stays the main line, and tasks 70, 71 and 80 are unlocked.

**Items for task-70, noted in round 2.** The prompt's orientation "only what the intent needs" led Claude to drop each cut's frame, which the fixed screen treats as central; the orientation has to say so, without naming the Silences app. The rules row shows numbers without a label; grouping them by meaning belongs to the structure the rules build. The state of a decision should be a badge, not loose text.

## Limits

- **Who ran it.** The acceptance criterion says the comparison is made "com o brenner". The round pages record the orchestrator running it at brenner's request ("test it yourself"), through the contract and without synthetic clicks. No round page records a run with brenner present.
- **Sample.** One task, one window size for the verdicts, and one Claude proposal per round. The source does not measure the variance of the Claude proposal; the two rounds differ in time, attempts, cost and structure.
- **Verdicts are judgment.** They are the orchestrator's reading of screenshots. The source gives no score, and this page computes none.
- **Round-1 binary.** Not recorded (see Setup).
- **The after-fix Claude view is a fixture.** It was built from the round-1 structure. Below the fold the source has no rectangles, so that part of the layout is the author's choice, stated in the corrections page. The fixture shows the fixes working on that structure; it does not show what a new Claude proposal would look like.
- **Causes in round 1.** Round 1 names two implementation causes and one from the proposal. The corrections page fixes three implementation defects (row, slider, number format) and changes the prompt. The two lists differ, and this page keeps both.
- **Layout.** The row wraps in order, without grouping by meaning. The wrap only checks the horizontal axis of a stack, so a fixed child wider than the whole column still overflows (corrections page).
- **Regress.** The frames are synthetic bars, not the test pattern; the hash of an image in the regress is its size, and pixels are compared only when a layer changes. The Silences baseline depends on `claude` being on the PATH of the machine that blesses it; without it, the selector's projection changes. The corrections page says this was already so.
- **Before images.** The "before" images of the fixes are in a scratch folder outside the repository. The corrections page lists the steps to rebuild them.
