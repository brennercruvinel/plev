# plano: NLU infrastructure admin

artefato de plan-mode (vinha de `plans/` com codinome aleatorio). plano de
implementacao completo pra transformar o NLU TUI num admin de infraestrutura de
verdade. nota de classificacao no rodape.

## contexto

o NLU TUI de hoje tem 6 telas (dashboard, domains, dns, server, apps, batch) +
help, mas 4 sao placeholder (dns, server, apps, batch). o dashboard funciona com
dado estatico do hashsteam.lua, e a tela domains tem filtro/sort basico. nao tem
animacao, dado ao vivo, modal, nem interatividade real alem da navegacao.

objetivo: virar um admin de infra completo. todas as telas funcionais, dado ao
vivo das APIs (cloudflare, coolify, hostinger, namecheap, spaceship, vercel),
animacao rica com a identidade NLU (gradiente tiamati amarelo pro verde, estrelas
lime #BFFF00), e interatividade ao maximo (modais, expand/collapse, bulk ops,
confirmacao, toasts animados).

patterns aplicados, extraidos dos knowledge files (yazi, television, bottom):

- P1: event batching + render throttle (yazi)
- P2: partial vs full render flag (yazi)
- P3: layer-based action routing / modal input (yazi)
- P7: render gating by action type (television)
- P8: mode transitions + shared chrome (television)
- P9: auto-navigation from layout (bottom)
- P10: widget maximize/restore (bottom)
- P11: configurable update rate (bottom)

gradiente tiamati animado: ciclo de cor no tempo, GRAD_YELLOW pro
GRAD_GREEN_DARK pro GRAD_GREEN_BRIGHT em loop. aplicado no titulo "NLU
INFRASTRUCTURE", na borda do painel ativo, na barra de progresso, na selected
row. ~3s por ciclo (lerp speed 0.12 conforme animation-pattern-lerp.md).

estrelas NLU (star overlay): caracteres `✦` `✧` `⋆` `★` `✶`, posicoes
pseudo-aleatorias (seed por tick pro determinismo), pulse de opacidade 0.3 pro
1.0 pro 0.3 com periodo diferente por estrela. aparecem no fundo do dashboard, na
tela de loading, no splash, na decoracao de modal.

### event loop (P1 + P2 + P7)

```
loop {
    // 1. drena TODO evento pendente (batch)
    let events = drain_events(&rx);

    // 2. processa eventos, rastreia necessidade de render
    let mut render_level = RenderLevel::None;  // None / Partial / Full
    for event in events {
        let level = process_event(event, &mut app);
        render_level = render_level.max(level);
    }

    // 3. checa os canais de dado async
    while let Ok(data) = data_rx.try_recv() {
        app.apply_live_data(data);
        render_level = RenderLevel::Full;
    }

    // 4. tica as animacoes
    if app.animations_enabled {
        app.tick_animations();
        if app.has_active_animations() {
            render_level = render_level.max(RenderLevel::Partial);
        }
    }

    // 5. renderiza so se precisar
    match render_level {
        RenderLevel::Full => terminal.draw(|f| render_full(f, &app))?,
        RenderLevel::Partial => terminal.draw(|f| render_partial(f, &app))?,
        RenderLevel::None => {} // pula o frame inteiro
    }

    // 6. rate limit: min 16ms entre frames (~60fps max)
    sleep_until_next_frame();
}
```

### async data layer

```rust
// data/live.rs
pub enum LiveData {
    ServerMetrics(ServerMetrics),         // CPU, RAM, Disk, Uptime
    CfZones(Vec<Zone>),                   // Cloudflare zones
    CfDnsRecords(String, Vec<DnsRecord>), // zone_id, records
    CoolifyApps(Vec<CoolifyApp>),         // Applications
    CoolifyServers(Vec<CoolifyServer>),   // Servers
    DomainHealth(String, DomainHealth),   // domain, health result
    BatchProgress(BatchOp, usize, usize), // op, done, total
    Error(String, String),                // source, message
}

pub struct ServerMetrics {
    pub cpu_percent: f64,
    pub ram_used_mb: u64,
    pub ram_total_mb: u64,
    pub disk_used_gb: f64,
    pub disk_total_gb: f64,
    pub uptime_secs: u64,
    pub load_avg: [f64; 3],
    pub containers: Vec<ContainerStatus>,
}
```

tasks de background via tokio::spawn, comunicam por mpsc channel. auto-refresh:
poll coolify + hostinger a cada 30s (configuravel). on-demand: dns lookup, health
check, batch ops, disparado por acao do usuario. cancellation: CancellationToken
por task pra cancelar quando troca de tela.

## fases de implementacao

### fase 1: core, theme + event loop + async (fundacao)

arquivos: theme.rs (rewrite), tui/mod.rs (major), event.rs (enhance),
animation.rs (new), data/live.rs (new), app.rs (major).

theme.rs traz a paleta NLU inteira, mais `gradient_color(t: f64) -> Color` que
interpola GRAD_YELLOW pro GREEN_DARK pro GREEN_BRIGHT,
`star_positions(width, height, seed) -> Vec<(u16, u16)>`, e os styles
`gradient_text()`, `active_border()`, `star_char()`.

animation.rs e o sistema de animacao: `AnimationState { tick, gradient_phase,
star_phases }`, `tick_animations()` que avanca tudo por 1 frame,
`gradient_color_at(phase)`, `star_opacity_at(idx, phase)`,
`transition_effect(from, to)` com tachyonfx. screen enter: fade_in 200ms. exit:
fade_out 100ms (cached). widget appear: slide_in from bottom 150ms.

event.rs ganha `drain_events(rx) -> Vec<AppEvent>`, que drena tudo sem bloquear,
mantendo o tick rate mas processando batch de keys. tui/mod.rs implementa o loop
de cima, com o enum RenderLevel (None/Partial/Full), integra o data_rx pros dados
async, e capa o frame rate em 60fps. data/live.rs traz o LiveData enum completo,
ServerMetrics e ContainerStatus, e o LiveState no App. app.rs expande o estado
(modal_stack, input_context, live, anim) e os metodos push_modal(), pop_modal(),
apply_live_data(), movendo a logica de tick pra tick_animations().

### fase 2: widgets reutilizaveis

todo o `tui/widgets/`.

sparkline.rs: mini grafico de serie temporal com braille (⣀⣤⣶⣿) ou block
(▁▂▃▄▅▆▇█), buffer circular de 60 pontos (1 por segundo numa janela de 1min), cor
no gradiente NLU (verde baixo, amarelo alto), ponto novo entra da direita com
slide.

progress.rs: barra de progresso com gradiente NLU na parte cheia, porcentagem
centralizada, modo indeterminado (bloco que vai de ponta a ponta), suporta label
("Updating NS... 42/155").

modal.rs: container de modal/popup, borda com sombra (offset +1, +1 escuro),
titulo na borda de cima, botoes no rodape (OK/Cancel, Tab alterna), borda com
gradiente NLU animado, tachyonfx fade_in ao abrir e fade_out ao fechar.

toast.rs: notificacao no canto superior direito, tipos Success (verde), Warning
(amarelo), Error (vermelho), Info (lime), auto-dismiss em 5s com fade_out nos
ultimos 500ms, stack de no maximo 3 visiveis.

table_ext.rs: tabela avancada, sort indicators (▲/▼) no header da coluna ativa,
selected row com gradiente NLU pulsando, alternating row colors (SURFACE/BG_DEEP),
hints de resize de coluna, scroll indicator na borda direita.

logo.rs: ASCII art "NLU" em letra grande (figlet-style), gradiente animado nas
letras, estrelas piscando ao redor, versao compacta (1 linha) e expandida (7
linhas).

confirm.rs: dialog "Are you sure? [Y]es / [N]o", borda vermelha pra acao
destrutiva, amarela pra bulk, teclado y/n ou Tab+Enter.

### fase 8: batch

arquivo: batch.rs (new). layout: box de Operations no topo, box da last operation
com progress no meio, box de History embaixo. (mockup ASCII na fonte.)

cinco operacoes bulk: 1) NS update, atualiza o NS de todos os dominios nos
registrars certos. 2) CF activate, ativa todas as zones pending. 3) health check,
DNS resolve + HTTP GET por dominio. 4) sync registry, compara hashsteam.lua com o
dado real do CF. 5) export, gera relatorio em texto/JSON.

funcionalidades: dry-run mode (D alterna, mostra o que faria sem executar). progress
bar animada com gradiente NLU, em tempo real. status por dominio com scroll. cancel:
Esc cancela a operacao em andamento (com confirmacao). history das ultimas 10 ops no
SQLite cache. summary com totais de ok/skip/falha + duracao. confirmacao antes de
iniciar, mostrando quantos dominios serao afetados.

### fase 9: help + polish final

arquivo: help.rs (enhance). context-sensitive (mostra os keybindings da tela atual
primeiro), searchable (/), sections com icone e cor, quick reference card estilo

polish geral: tab bar com indicador de tela ativa no gradiente NLU. status bar com
o modo atual (NORMAL/SEARCH/COMMAND), timestamp e indicador de refresh. transicoes
entre telas com fade via tachyonfx. loading com spinner de estrelas NLU. error state
com borda vermelha pulsante. empty state com estrelas decorativas. resize handling
responsivo. mouse support (click em tab, scroll em lista).

## input system (P3)

```rust
pub enum InputContext {
    Normal,        // navegacao principal
    Search,        // digitando query
    Command,       // : command mode
    Dialog,        // modal com botoes
    DetailView,    // painel de detalhe expandido
    LogViewer,     // scroll de logs
    Editing,       // editando campo (DNS record)
}
```

cada context tem o seu keymap. Normal: 1-6 (telas), j/k (nav), Enter (detail),
Space (select), / (search), q (quit). Search: chars (append), Backspace (delete),
Esc/Enter (sai). Dialog: Tab (proximo botao), Enter (confirma), Esc (cancela), y/n
(atalho). DetailView: j/k (scroll), Esc (fecha), m (maximize), acoes inline.
LogViewer: j/k (scroll), G (bottom/follow), q/Esc (fecha). Editing: chars,
Backspace, Ctrl+A (select all), Esc (cancela), Enter (salva).
