## conteudo normalizado

regra de escopo. quando o user diz "documenta nosso MCP", ele fala do codebase
em `/nlu/mcp/infra/affine/server/src/`, nao das tools de terceiro (Hostinger,
Vercel e afins). ler os `.ts` de verdade antes de escrever qualquer coisa. na
sessao 21 muito tempo foi perdido documentando catalogo de tool externo quando
o que ele queria era a doc do fork dele. usar Agent Explore para ler o source
primeiro. na duvida, perguntar: documento o codebase ou as tools?

preserveEmbeds. a partir da sessao 22, `replace_doc_with_markdown` aceita
`preserveEmbeds: true`. usar para manter `embed_linked_doc`, `embed_synced_doc`
e blocos de database intactos no replace. sem isso, os `embed_linked_doc`
(que criam filhos na sidebar e link bidirecional) sao destruidos. quando o doc
tem filho na sidebar ou database, sempre passar `preserveEmbeds: true`, e
checar com `list_children` antes se houver duvida.

collections via mcp. a partir da sessao 22 da para criar collection pelo
`create_collection`. tag e collection seguem features separadas: collection e
view de filtro salva em `setting.collections` do Yjs, tag e metadado de doc.
usar `create_collection` com `filterTag` para collection baseada em tag, ou
`allowList` para selecao manual de doc.

sem emoji na doc, a nao ser que o user peca. ele foi direto: precisa da
documentacao completa, nao de uma lista de emoji. doc profissional e texto
limpo. titulo e corpo no AFFiNE: so texto plano.

batching de tag. usar `batch_add_tag` (max 50 docs) no lugar de chamar
`add_tag_to_doc` em loop. uma conexao WebSocket so, bem mais rapido. a sessao 21
gastou 8 chamadas separadas; a 22 resolveu com batch. para 2 docs ou mais
precisando da mesma tag, sempre batch.
