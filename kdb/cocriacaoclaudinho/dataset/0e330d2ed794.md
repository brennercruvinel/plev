Expo web support uses Metro resolver shims at `src/shims/` configured in `metro.config.js`.

**Key shims (as of 2026-03-20):**
- `react-native-skia-web.ts` — full Skia API stub (SVG, matchFont, clamp, interpolate, etc.)
- `react-native-worklets-web.ts` — worklet scheduling stubs
- `expo-sqlite-kv-store-web.ts` — localStorage fallback (SharedArrayBuffer not available on web)
- `native-modules-web.ts` — generic noop for native-only modules
- Plus shims for haptics, purchases, firebase, google-signin, apple-auth, etc.

**Why:** The app is mobile-first but needs web loading for dev/preview. Native modules crash on web without shims.

**How to apply:**
- When adding new native modules, add a corresponding web shim entry in `metro.config.js`
- The prefix match in metro.config.js excludes `/package.json` requests — this is critical for version checks (Reanimated validates worklets version via package.json)
- Never use duplicate `export default` in shims — causes "Cannot redefine property: default"
- `expo-sqlite/kv-store` cannot work on web without COOP/COEP headers — always use the localStorage shim
