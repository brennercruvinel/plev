> ### 1.2 data collection architecture
> 
> ```
> input thread (key/mouse polling)
>  |
> main thread (event handling + ui) <-> datastore (in-memory cache)
>  ^
> collection thread (periodic refresh) -> data snapshot
>  |
> cleaning thread (prune old data every n seconds)
> ```
> 
> - **polling interval:** configuravel (default 1-3s)
> - **smart refresh:** operacoes caras (battery, disks) rodam a cada 60s
> - **time-series:** chunked storage via `timeless` crate, deduplicacao automatica
> - **retention:** configuravel (default ~10min), cleaning thread poda dados antigos
> - **usedwidgets:** so coleta metricas de widgets visiveis (zero overhead em widgets ocultos)

> ### 1.3 ui architecture

> - **framework:** ratatui 0.30 + crossterm backend

> - `timegraph` - graficos time-series com scatter + line, eixo linear/log, legend configuravel
> - `datatable<t, h, s>` - tabelas genericas com type-state pattern (sortable/unsortable)
> - `pipegauge` - battery indicator
> - `paragraph` - texto simples

> **datatable features:**
> - selecao com scroll tracking
> - column widths auto-calculados, cached
> - sort por qualquer coluna (click ou key)

> ### 1.4 process query language
> 
> parser hand-written com sintaxe:
> ```
> chrome && cpu>50 # chrome com >50% cpu
> pid=^1234$ # pid exato (regex)
> user=root or user=docker # processos de root ou docker
> "bash" and mem<100 # bash com <100mb
> ```

> **atributos:** name, pid, cpu, mem, state, user, r (read rate), w (write rate), read, write
> **operadores:** `=`, `>`, `<`, `and`, `or`, parenteses

> ## 6. cargo-sweep
> 
> **repo:** github.com/holmgr/cargo-sweep | **stars:** ~926 | **lang:** rust | **version:** 0.8.0
> 
> ### 6.1 cleaning strategies
> 
> | estrategia | flag | descricao |
> |------------|------|-----------|
> | time-based | `--time n` | mantem artifacts acessados nos ultimos n dias |
> | toolchain | `--toolchains stable,nightly` | mantem artifacts de toolchains especificas |
> | installed | `--installed` | mantem artifacts de todas toolchains instaladas |
> | max size | `--maxsize 5gb` | remove mais antigos ate caber no limite |
> | stamp mark | `--stamp` | cria marcador temporal |
> | stamp clean | `--file` | limpa tudo anterior ao marcador |
> 
> ### 6.2 fingerprint-based identification
> 
> cargo armazena hash de 16 chars hex em cada artifact:
> `deps/libfoo-a1b2c3d4e5f6g7h8.rlib`
> 
> **diretorios limpos:** `.fingerprint/`, `build/`, `deps/`, `native/`, root artifacts
> **preservados:** `examples/`, `incremental/`
> 
> **toolchain hash:** extrai `rustc` hash dos `.fingerprint/*.json` files
> - dual-hash compatibility: siphasher (rust <1.85) + stablehasher (>=1.85)
> 
> ### 6.3 maxsize algorithm
> 
> 1. scan total size do target/
> 2. se < limite, nada a fazer
> 3. scan todos fingerprints, ordena por recencia
> 4. itera do mais antigo, acumulando ate atingir `bytes_to_remove`
> 5. hashset de hashes a manter, deleta o resto
> 
> ### 6.4 stamp workflow
> 
> ```bash
> cargo sweep --stamp # marca ponto no tempo (sweep.timestamp)

> ## 7. cargo-clean-all
> 
> **repo:** github.com/dnlmlr/cargo-clean-all | **stars:** ~213 | **lang:** rust | **version:** 0.6.4
> 
> ### 7.1 project detection
> 
> - **thread pool:** crossbeam channels + n threads (default=num_cpus)
> - **work-stealing:** unbounded mpsc jobs queue
> - **detection:** `cargo.toml` + `target/` existencia
> - **smart skipping:** `.git/`, `.cargo/`, user `--skip` paths
> - **depth limit:** `--depth n` (limita recursao do target/)
> 
> ### 7.2 interactive selection
> 
> - **framework:** `dialoguer::multiselect`
> - **pre-selecao:** baseada em filtros (size, age, ignore dirs)
> - **override manual:** usuario pode toggle individual
> - **confirmacao:** `dialoguer::confirm` (bypass com `-y`)
> - **display:** nome (verde bold), size, data, path completo
> 
> ### 7.3 filtering
> 
> | filtro | flag | default | descricao |
> |--------|------|---------|-----------|
> | size | `--keep-size` | 0 | ignora projetos menores que n |
> | age | `--keep-days` | 0 | ignora compilados nos ultimos n dias |
> | ignore dirs | `--ignore` | - | pre-deseleciona (ainda detecta) |
> | skip dirs | `--skip` | - | pula completamente (performance) |
> | depth | `--depth` | 0 (unlimited) | limita recursao do target/ scan |
> 
> ### 7.4 cleaning
> 
> **full removal (default):** `remove_dir_all::remove_dir_all(path)` (parallel feature)
> **keep empty (`--keep-empty-target`):** deleta conteudo, mantem diretorio
> **preserve executables (`-e`):** move binarios para `./executables/{profile}/` antes de deletar
> 
> ### 7.5 progress & display
> 
> - `indicatif` para 3 fases: scanning spinner, size computation bar, deletion bar
> - `colored` para syntax highlighting
> - `bytefmt` para parse/format de tamanhos
> - `chrono` para timestamps
> 
> ### 7.6 patterns notaveis
> 
> 1. **work-stealing via channels** (sem thread pool crate, crossbeam puro)
> 2. **two-pass selection** (pre-select por filtros, override interativo)
> 3. **executable preservation** (move antes de deletar)
> 4. **lexical depth tracking** (option<usize> decrementado por recursao)
> 5. **canonical path comparison** (handles symlinks e case-insensitive fs)
> 6. **parallel deletion** via `remove_dir_all` crate
